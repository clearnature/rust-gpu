## 二、已确认的修复

### 1. v0 未初始化（GFX1200 VGPR 初始化问题）
- **文件**: `src/t0/asm_emitter.rs`
- **问题**: GFX1200 的 VGPR 不像 GFX1100 那样由硬件初始化。`thread_id_x()` 返回 `VReg(0)`，但 v0 未被初始化为 lane ID。
- **修复**: 在 GFX1200 prologue 中加入 `v_mbcnt_lo_u32_b32 v0, exec_lo, 0`
- **状态**: ✅ 已应用

### 2. `emit_arg_loads()` 调用缺失
- **文件**: `src/t0/compile.rs`, `src/t0/tile_ssa_lower.rs`
- **问题**: 手动构建 `T0Kernel` 时，如果忘记调用 `emit_arg_loads()`，SGPR 不会从 kernarg 加载指针值，导致使用垃圾地址。
- **状态**: BlockDSL 路径（`tile_ssa_lower`）已正确调用；手动 T0Kernel 使用时需注意。

### 3. `dispatch` 使用 `synchronize()` 替代 `wait_idle()`
- **文件**: `src/ignis/gpu_context.rs`
- **问题**: `wait_idle()` 只等 read_ptr 前进，不做 L2 cache writeback。GPU 写入的数据 CPU 可能看不到。
- **修复**: `self.queue.wait_idle()` → `self.queue.synchronize()`
- **状态**: ✅ 已应用

## 三、已定位但未修复的根因

### 核心问题：global_load 读到垃圾数据

| 测试 | 结果 | 说明 |
|------|------|------|
| `store_constant` | ✅ 通过（需 GPU 正常） | 只做 store，不做 load |
| `load_store_no_mask` | ❌ 读到 0.13... 而非 1.0 | `global_load_b32` 读到错误数据 |
| `add_forward_backward` | ❌ 全零 | store 不执行（可能是 load 导致的连锁问题） |

**关键发现**:
- `global_store_b32` 写入正确 ✅
- `global_load_b32` 读到垃圾 ❌
- 汇编编码与 llvm-mc 完全一致 ✅
- kernarg 地址正确 ✅
- 问题可能是 **GPU L2 cache 一致性**：CPU 写入 GTT 内存后，GPU L2 没有 invalidation

**参考**: tinygrad 在每次 dispatch 前用 PM4 `ACQUIRE_MEM` + `GL2_INV` 做 L2 invalidation。T0 没有这一步。

## 七、历史根因记录（来自项目记忆）

之前的 `output全零` 问题有 **7 个叠加根因**（已在 PROJECT_MEMORY.md 记录）：

1. atomic 返回没等 vmcnt
2. 64 位地址 VGPR 未连续分配
3. WG 内 4 wave 各自认领不同 tile → LDS 覆盖
4. GFX1200 2-WG 下 TGID.x = -1
5. readfirstlane 高压下恒定垃圾
6. persistent 首 tile LDS 竞态
7. **核心误判**：以为 ≥4WG 是硬件死锁（实际不是）

**关键结论**: HIP 多 WG 正常，T0 的 AQL 队列也支持多 WG。"硬件限制"是误判。
