# T0 寄存器架构升级 — 顶层设计（2026-08-27）

> 决策：不再对寄存器相关 bug 逐个打补丁。按本设计把「寄存器类（RegClass）+ 保留寄存器单一事实源 + 地址类物理隔离 + 跨阶段存活保守化」推进 RegAlloc 与 IR 层，一次性关闭 voffset 折叠、xr_0_tmp 别名、v0 覆盖、VCC 破坏等同类问题。

### 1.2 真实缺口（本设计要补的）

| 缺口 | 证据 | 类别 |
|------|------|------|
| 保留寄存器集合散落各处、无单一事实源 | v0/s63 各在两处重复定义，s0-4 仅靠"从 5 起"约定 | A |
| 无"分配器输出"验证（映射结果可能踩保留寄存器而不自知） | 无任何 post-allocation check | A |
| **地址值无寄存器类**：地址 VReg 与普通临时值同池、可被折叠/别名/复用 | xr_0_tmp 别名 WT 基址（ksub=1 frag_a 读到 WT 数据）；voffset 折叠历史 bug | **B（核心缺口）** |
| 跨 ksub/跨循环基址无保守存活保护 | 基址在 ksub 间被复用；现有循环扩展只延 last_use 到 loop_end，无隔离 | C |
| 使用点直接引用/写入 VReg(0)（探针读 tid、内部 scratch 写 v0）无检查 | `tile_ir.rs:2654/1150` 等直接引用 VReg(0) | A |

### 1.3 边界说明（重要）

P2 残留的 C_RAND 数据偏差（K=16→156、K=48→604、K=64→824）来自**store 侧 col_chunk 线性 lane 映射 与 WMMA 读侧 XOR swizzle 映射不一致**——这是 tile_ir 数据布局语义问题，**不属于寄存器架构缺口**。本设计不承诺修复它；两条线并行：
- 本设计：关闭寄存器类 bug（xr_0_tmp 别名等，属同一二进制内的确定性问题）；
- tile_ir 语义线：统一两个 lane 映射（P2 残留根因）。

## 2. 顶层设计

### 2.1 寄存器分类体系（RegClass）

在 `ir.rs` 引入三分类，VRegAlloc 增加 `class` 字段：

```
enum RegClass {
    Normal,      // 普通临时值：可自由复用、可折叠（现状行为）
    Address,     // 地址值：物理隔离、不复用普通槽、不折叠、不 spill
    Accumulator, // WMMA 累加器：对齐组（Align4/8），现状已由 alignment 表达
}
```

- **Normal**：默认类，行为与现状完全一致（回归零风险）。
- **Address**：地址计算 VReg（ds_load/global_load/store 的 voffset、LDS 基址、k_byte_off、lane_swizzle 等）。
- **Accumulator**：WMMA C 片段（已通过对齐隐含，显式化便于 verifier）。

### 2.2 保留寄存器单一事实源（新模块 `src/t0/regs.rs`）

```
VGPR:  v0 保留（workitem_id_x）
SGPR:  s0:s1 kernarg ptr、s2:s3:s4 TGID、s63 SOFFSET_ZERO
隐式:  VCC(64bit)、EXEC(64bit)、M0(32bit)、TTMP0-15、PC、SCC(1bit) —— 不进可分配集合
常量:  SGPR_BASE=5、MAX_VGPRS=254、MAX_SGPRS=106
API:   is_reserved_sgpr(n)、is_reserved_vgpr(n)、allocatable_sgpr_range()…
```

两个分配器（legacy + SSA）全部改用该模块常量；删除各处散落字面量。

### 2.3 地址类物理隔离（B 类核心机制）

**设计：双池、按类回收、高水位各自推进。**

- 两个互不相交的物理池：`normal_pool`（现有 FreePool，v1 起）与 `addr_pool`。
- 地址区间到期回收进 `addr_pool`，普通区间回收进 `normal_pool`——**池间永不复用**（隔离的充分条件）。
- 地址分配优先取 `addr_pool` 空闲槽，否则推 `addr_pool` 高水位；普通同理。
- 峰值压力 = max(存活普通 + 存活地址)，与现状相同（**不增加 VGPR 压力**，区别于"顶部分区常驻"方案）。
- 地址区间 **永不 spill**（数量编译期已知且小；溢出即编译错误而非静默降级）。
- 对齐：地址对 Align2 在 addr_pool 内处理；WMMA 累加器对齐在 normal_pool 内处理，互不影响。

**为什么这能关闭整类 bug**：xr_0_tmp 别名 WT 基址、voffset 折叠、ksub 地址重算别名——本质都是"地址值被分配器当作普通临时值复用"。物理隔离后，地址值只可能与其他地址值冲突（而地址值之间通常无活区间重叠，因为一个地址被 ds_load 消费前另一个不会复用）；verifier 负责兜底。

### 2.4 跨阶段存活保守化（C 类）

- 地址类区间：在现有循环扩展（last_use → loop_end）基础上，**若区间跨越任何 loop back-edge，扩展到整个最内层循环**（保守），且由于 2.3 隔离，普通值永远无法侵占地址槽。
- 即：C 类机制在 B 类隔离之上**几乎免费获得**（隔离已保证跨阶段安全），剩余工作是给地址类区间显式标记"跨循环"供 verifier 断言。

### 2.5 验证层（防虚假完成）

新增 `verify_allocation(&RegAlloc)`（编译管线固定调用）：
1. 无任何 vgpr_map 值 ∈ 保留 VGPR（物理 0 仅允许 VReg(0)→0 的 tid 映射）；
2. 无任何 sgpr_map 值 ∈ {0..4, 63}；
3. 地址类 VReg 的物理寄存器与普通类 VReg 的物理寄存器**集合不相交**；
4. 地址类区间无 spill 记录。

`isa_verifier.rs` 强化：
5. VCC 写→读对之间不得插入第二个 VCC 写（现状只查 carry-in 读，补全 v_cmp→v_cndmask 相邻性）；
6. 禁止任何 Op 把 VReg(0) 作为**目的**寄存器（写 tid 即死；读取允许）。

### 2.6 tile_ir 采纳与清理

- 热地址计算全部改用 `alloc_addr_vreg()`：`x_lds_reads_raw/0/16`、`wt_raw/base_0/base_16`、`k_byte_off`、`lane_swizzle`、gmem 基址、store 基址、`next_k_off` 等。
- **移除已失效的补丁**（由类机制取代）：
  - ksub>0 的 fresh-VReg 内联重算（`tile_ir.rs:2611-2621`）→ 回到 xr_0_tmp 路径（现在安全）；
  - `tid_copy`（`tile_ir.rs:1148-1151`）→ 直接使用 VReg(0)（v0 受保护）；
- **保留**（语义修复，非寄存器问题）：P1 K-OOB mask、P2 prefetch、read-side mask。
- 探针（T0_PHASEB_PROBE）保留在树内（env 门控），调用点维持 None。

## 4. 风险与对策

| 风险 | 对策 |
|------|------|
| 双池增加峰值 VGPR → CWSR 危险区(>252) | 峰值 = 存活地址+存活普通，与现状相同；地址永不 spill 但数量编译期已知；溢出即报错 |
| 地址类改坏性能（地址槽不复用） | 地址数量 ~20-40，且隔离后 xr_0_tmp 等不再需要 fresh-VReg 重算（省指令）；S6 性能门把关 |
| 改动面大引入回归 | 分阶段 + 每阶段绿门；S1 不改变任何分配行为（纯常量替换+验证） |
| 与 P2 语义线混淆 | 本设计明确边界（§1.3）：寄存器架构不背 P2 残留的锅 |

## 7. 行业调研校准（子代理简报：docs/gpu-special-registers-briefing.md，57 项锚点验证 PASS）

| 我们的设计 | 行业做法 | 校准结论 |
|-----------|---------|---------|
| v0 永久保留（不分配） | LLVM：v0 是入口 live-in，prologue 拷贝后即可复用；**不**保留 | T0 全程读 v0 当 tid → 永久保留更简单且正确；拷贝出是 LLVM 的优化选项 |
| s0-4 / s63 保留 | LLVM getReservedRegs 位图 + TableGen isAllocatable=0 双通道 | 与 LLVM 双通道建模一致；s63=SOFFSET_ZERO 是 GFX1200 特有 |
| VCC/EXEC 隐式副作用 | ACO：窗口外编号 + 指令级 needs_vcc/can_write_m0 特判；RDNA4 pseudo-scalar 禁 VCC 目标 | S5 的 VCC 相邻性检查应仿 ACO 指令级特判 |
| Address 类（物理隔离） | **LLVM/ACO 都没有**指针寄存器类（getPointerRegClass unreachable；ACO 无 pointer RegType） | 比业界更保守——因 T0 反复踩 liveness 坑，隔离是合理加固；但成本是峰值压力略增，需裁剪转换集 |
| 基址跨循环不 pin | LLVM 不 pin，靠循环感知 spill 偏置 + remat + 入口预载 | T0 的地址池隔离是更强的保证，代价可接受 |
| tinygrad | 完全委托 LLVM（compiler_llvm.py/compiler_amd.py）；renderer/amd 只是编码库 | 不提供寄存器分配参考；其 dsl.py 的寄存器编号表（NULL@124/M0@125）可用于编码验证 |
